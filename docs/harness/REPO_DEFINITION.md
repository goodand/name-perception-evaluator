# 저장소 정의 (초안, 2026-11-05)

이 저장소는 **조건을 충족하는 용어(이름)를 고르게 돕는다.** 후보를 맥락 없는 별도 모델에게 이름만 보여 주고, 받아들여진 뜻이 조건을 충족하는지 규칙으로 판정해 고른다.

- 대상: 저장소 이름, GUI 유형 이름, 템플릿 칸 이름 등 새로 짓는 용어
- 범위 밖: 명명 규칙 준수 검사(린터), 무작위 생성
- 웹 검색은 범위 안(2026-11-06): 격리 검색자가 설명문만 보고 낱말을 찾고, 바깥 에이전트가 수정 프로토콜로 점검한 뒤 조합 키워드 풀에 넣는다

## 1. 용어가 충족해야 할 조건

| 구분 | 조건 | 판정 방법 |
|---|---|---|
| 필수 | M1. 처음 보는 사람이 의도한 뜻(대상+역할)으로 읽는다 | 단독 설명문이 브리프 `must` 신호어 묶음을 모두 채움(통과율) |
| 필수 | M2. 사람 독자 관점(UX·최종 사용자)에서도 M1 | `--human` 관점 지시문 |
| 필수 | M3. 키워드 3개 이하, 구분자로 형식화(영어는 소문자+하이픈, 코드 식별자는 밑줄; 한국어 용어에도 같은 키워드 수 기준) | `namecheck lint` |
| 필수 | M4. 이름 안에 대상(무엇을 다루는지)이 있다 | 프로필 `target_word_required`, 통과율에서 드러남 |
| 필수 | M5. 같은 묶음의 다른 용어와 같은 뜻으로 읽히지 않는다(묶음일 때) | `namecheck overlap` |
| 선택 | O1. 다른 뜻으로 읽힌 표본이 없다(오독 0). 항상 달성할 수는 없으므로 순위 기준: 오독 0 우선, 없으면 오독률 최저 | `choose()` 게이트 → fallback |
| 선택 | O2. 통과율이 높다 | `choose()` |
| 선택 | O3. 동점이면 기존안 유지 | `choose()` baseline |
| 참고 | R1. PyPI·npm·GitHub 이름 충돌 | `availability`(빼지 않음) |

모델(Sonnet·Haiku·gpt)은 결과가 같아야 하는 조건이 아니다. 여러 모델의 설명을 다각도로 보고 판정하는 입력이다.

## 2. 조건 달성 전략

| 조건 | 전략 |
|---|---|
| M1·M4 | 브리프에 목적·사람 행동 삼중항(주체·행동·대상)을 먼저 쓴다. 이름은 `[대상]-[역할]` |
| M1·M2 공통 | 생성자에게는 하는 일·사람 행동만 준다. 분야 이름·금지 목록·실패 단어는 주지 않는다(넣은 신호는 끌어당김) |
| M1·M2 공통 | 답변자에게는 이름만, 하나씩(solo) 준다. 생성자·답변자 지시문은 개발·SW 단어 사전(범용 사전 + 자주 새는 단어 사전, 예: JSON)으로 검사한다. 걸린 지시문은 보내지 않고, 격리 모델이 고친 뒤 다시 검사하는 루프를 최대 3회 돈다. 깨끗해진 지시문만 보낸다. 실행기 제약 같은 예외는 이유를 기록해 허용한다 |
| O1 | 규칙 판정 뒤 설명문을 직접 읽어, 규칙이 놓친 오독을 `misread_as`에 보강하고 다시 판정한다(규칙 먼저, 자연어 최적화는 마지막) |
| O1 | 신호어는 단어 하나보다 동작+결과 쌍. 이름 자체 단어는 신호어로 쓰지 않는다 |
| M5 | 묶음은 용어마다 자기 `must`를 따로 적어 겹침을 센다. 겹친 쌍은 하나를 바꾼다 |
| O2 | 여러 묶음을 독립 생성 → 키워드 통계(`stats`)로 경향만 본다. 후보는 생성 결과·사용자 후보 그대로(평가자가 조합하지 않음: 평가자 편향이 들어간다) |
| M1·M2 | 답변자를 섞어(Sonnet·Haiku·gpt, 로컬 LLM은 GPU가 비면) 모델마다 3회, 설명을 다각도로 본다 |
| 공통 | 사용자 후보를 먼저 돌린다. 규칙을 고치면 새 표본으로만 재판정(rule_hash) |
