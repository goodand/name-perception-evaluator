# 이름 검증 하네스 안내 (Claude 모델만으로 동작)

이 하네스는 이름 후보를 **맥락 없는 별도 모델에게 이름만 보여 주고**, 그 모델이 받아들인 뜻이 의도와 맞는지 규칙으로 판정한다. 한 번이라도 다른 뜻으로 읽힌(오독) 후보는 뺀다.

- 설치: `bash setup.sh` (가상환경, `claude` CLI 확인, 오프라인 시험)
- 진입점: `python scripts/namecheck.py <명령> … [--json]`
- 기준(주제 무관): `docs/harness/naming_profile.json`
- 주제별 평가자 맥락: `docs/harness/briefs/<주제>.json` (예: `name-harness.json`)
- 실패 사례(회귀용): `docs/harness/naming_failures.json`
- 설계 기록: `docs/harness/name_harness_v2.md`
- 저장소 정의(조건·전략): `docs/harness/REPO_DEFINITION.md`
- 결정·질문 기록: `docs/harness/DECISION_LOG.md` (사용자가 정한 것과 물은 것을 함께 남긴다)
- 선택 답변자: gpt-6-luna(OMP 실행기가 있는 PC — 경로는 `NAME_HARNESS_OMP_ROOT` 환경 변수로 지정), LM Studio 로컬 LLM(서버가 켜진 PC — 주소는 `LMSTUDIO_URL`, 기본 127.0.0.1:1234). `namecheck doctor`가 셋(claude·gpt·qwen)의 가능 여부를 보여 준다. 없으면 Claude만으로 돈다

## 하네스 안의 주체(재현되지 않는 모델만, 서로 맥락 공유 없음)

| 주체(초안 용어) | 받는 것 | 내는 것 | 명령 |
|---|---|---|---|
| 검색자 | 설명문(하는 일·사람 행동)만 | 사람들이 쓰는 낱말·뜻·출처 | `search` |
| 작명자 | 하는 일·사람 행동만(평문, 역할 부여) | 하이픈 이름 + 한 줄 | `generate` |
| 첫눈 독자 | 이름 하나 + 평문 지시문 | 자유 서술 1~2문장 | `run` |
| 대조 평가자 | 의도·이웃 개념 이름·설명문(이름은 받지 않음) | 구조화된 출력: 번호마다 같음/다른 뜻/불분명 + 읽힌 뜻(경고만) | `run --review` |

판정·사전 검사(영어 표제어 simplemma: 일치는 막음, 낱말 안 포함은 경고)·겹침·조합·조사 맞춤(Kiwi)은 같은 입력에 같은 결과라 주체가 아니라 장치다. 지시문을 고쳐 쓰는 모델은 두지 않는다: 지시문은 틀(`prompt_templates.json`)로 고정하고 바깥 에이전트가 빈칸만 채운다.
첫눈 독자·작명자·검색자에게는 형식 말(schema·JSON)을 넣지 않는다. 대조 평가자는 의도를 알고 보기에서 고르는 주체라 형식 신호의 영향이 작아 구조화된 출력을 쓴다(주체마다 다르게 정한다). 호출마다 `<out>/usage.jsonl`에 주체·모델·시간·토큰·비용이 쌓이고, report.md 끝에 주체별 합계가 붙는다. 예외: 선택 답변자 gpt는 동봉 실행기가 형식 꼬리를 요구해, 쓸 때만 앞에 역할 부여(화면 글 작가)를 붙여 희석한다.

## 하네스 밖의 주체(네 주체)

| 주체 | 보는 것 | 이 문서에서 볼 절 |
|---|---|---|
| A. 도구를 쓰는 에이전트 | 텍스트(`--json`, 종료 코드) | 1 |
| B. A를 쓰는 사람 | 그림·표(`report.md`, 보고서 그림) | 2 |
| C. 도구를 고치는 에이전트 | 텍스트(코드·테스트·비교 결과) | 3 |
| D. C를 쓰는 사람 | 그림·표(비교 표, 실패 사례) | 4 |

주체마다 받는 형식이 다르다. 에이전트는 텍스트, 사람은 그림·표로 받는다. 같은 결과를 두 형식으로 바꾸는 것이 변환기다(`--json` ↔ `report.md`).

## 무엇을 스크립트로, 무엇을 스킬로

| 일 | 형태 | 이유 |
|---|---|---|
| 형식 검사, 위험 단어·길이 검사, 충돌 조회, 수집, 판정, 선택, 기존안 비교, 키워드 통계 | 스크립트(`namecheck.py`) | 반복되고 선택지가 적다. 모델과 무관하게 같은 결과 |
| 브리프 쓰기(목적·사람 행동·이웃 개념), 관점별 지시문 고르기, 설명문을 읽고 오독 신호어 보강 | 에이전트 스킬 | 창의성이 필요하거나, 변수가 많거나, 관점에 따라 프롬프트가 달라진다 |

자연어 지시(스킬 md)는 검증이 어렵다. 규칙으로 고칠 수 있는 것을 먼저 스크립트에 넣는다.

## 1. 도구를 쓰는 에이전트(A)

| 주체 | 행동 | 대상 | 명령 |
|---|---|---|---|
| 에이전트 | 만든다 | 브리프 빈칸 틀(용어 정의 템플릿) | `namecheck brief-new <out.json>` → `<…>`를 채운다. `definition.pattern`(사람이 {xx}끼리 대조해 {yy}를 파악하고 {zz}를 결정한다)을 채우면 purpose가 자동으로 만들어진다 |
| 에이전트 | 검사한다 | 브리프 형식 | `namecheck brief-check <brief> --json` (실패 시 종료 코드 1) |
| 에이전트 | 만든다 | 후보 묶음(격리 생성) | `namecheck generate haiku,haiku,sonnet <out>/gen --brief <brief>` |
| 에이전트 | 조합한다 | 생성 묶음 키워드로 후보 추가 | `namecheck combine <out>/gen/*.json --top 30 --out <후보.txt>` (2개 이상 묶음에 나온 키워드만, [대상]-[역할] 자리, 한 이름 안 중복 없음, 기존 이름 제외. `--words <낱말.json>`이면 점검을 통과한 검색자 낱말을 쪼개 키워드 풀에 더한다. 결과를 `run`에 그대로 넣는다) |
| 에이전트 | 찾게 한다 | 사람들이 쓰는 낱말(검색자, 격리, 웹 검색) | `namecheck search <brief> <낱말.json> [--model sonnet] [--n 15] --json` (검색자 지시문이 사전에 걸리면 보내지 않음. 낱말마다 개발 용어 경고) |
| 에이전트 | 점검한다 | 검색자 낱말(남김·뺌) | `namecheck words-review <낱말.json> <결정.json> --json`. 결정: `{"decisions":[{"word","keep","reason","note"}]}`. 검색자가 내지 않은 낱말·정해진 보기(뜻이 다름·너무 넓음·개발 용어 경고·기타) 밖 이유·설명 없는 기타는 거부, 받아들인 항목은 못 바꿈. 0 끝남 / 2 `fix_only`만 다시 / 1 3회 넘어 멈춤(사람이 정함). 뺀 낱말은 사용자 확인용으로 따로 보인다 |
| 에이전트 | 채운다 | 지시문 틀 빈칸 | `python scripts/prompt_slots.py 답변자 <빈칸.json> --json`. 조사는 `{빈칸|이}`처럼 기본형으로 쓰면 한글 값은 Kiwi가 맞춘다. 영어·숫자로 끝나는 값은 조사 자리에 못 둔다(다시 채움) |
| 에이전트 | 센다 | 묶음 키워드 통계 | `namecheck stats <out>/gen/*.json --json` |
| 에이전트 | 거른다 | 후보 형식·길이, 위험 단어 | `namecheck lint <brief> <후보> --json` |
| 에이전트 | 조회한다 | 이름 충돌(참고 정보) | `namecheck availability <후보> --json` |
| 에이전트 | 확인한다 | 쓸 수 있는 답변자 백엔드 | `namecheck doctor --json` |
| 에이전트 | 돌린다 | 수집→오독 게이트→선택 | `namecheck run <brief> <후보> <out> [--human] [--answerers claude:haiku,gpt:gpt-6-luna,qwen:<id>] [--no-local] [--slots <빈칸.json>] --json` (보내기 전 지시문 검사: 개발·SW 단어·형식 요구가 걸리면 보내지 않는다. 답변자 지시문은 틀의 빈칸을 `--slots`로 채우고, 빈칸이 걸리면 종료 코드 2 → 걸린 빈칸만 다시 채워 다시 부른다(수정 프로토콜, `<out>/slot_gate.json`). 고정 지시문이 걸리면 종료 코드 1(틀을 고칠 일, 개발 쪽). 기록 `<out>/prompt_gate.json`. qwen이 있으면 LM Studio를 자동으로 켬. GPU를 다른 세션이 쓰면 `--no-local`) |
| 에이전트 | 다시 본다 | 설명문(격리 평가자, 사람 관점, 경고만) | `namecheck run … --review claude:sonnet` 또는 `python scripts/review_explanations.py <rules.json> <out.json> <표본…> [--view end_user\|ux]`. 평가자는 의도·이웃 개념 이름·설명문만 받고 규칙 신호어·판정·다른 후보는 받지 않는다 |
| 에이전트 | 찾는다 | 한 묶음 이름끼리 뜻 겹침(예: 칸 이름 10개) | `namecheck overlap --rules <이름마다 자기 must가 있는 rules.json> --samples <out>/*/*.jsonl --json` (A의 설명이 B의 must를 모두 채우면 겹침, 종료 코드 2 → 둘 중 하나를 바꾼다) |
| 에이전트 | 모은다 | 키워드별 오독률 | `namecheck risk --rules <out>/rules.json --samples <out>/*/*.jsonl --json` |

지켜야 할 것:
- 생성자에게는 브리프의 **하는 일과 사람 행동만** 간다(`gen_prompt`). 분야 이름·금지 목록·실패 단어를 프롬프트에 넣지 않는다. 하지 말라고 써도 들어간 신호는 끌어당긴다.
- 답변자에게는 **이름만** 간다(`collect_samples`가 `id`·`term`만 보냄). 생성자의 설명(`why`)도 답변자에게 주지 않는다.
- 답변자로 Agent 도구의 서브에이전트를 쓰지 않는다. CLAUDE.md·메모리가 보여 오염된다. `claude -p` 격리 실행(동봉 `claude_adapter.py`)을 쓴다.
- 독자가 사람이면(`audience`가 `end-user`·`mixed`, 또는 `--human`) UI/UX·최종 사용자 관점 지시문이 추가된다.

## 2. A를 쓰는 사람(B)

| 주체 | 행동 | 대상 |
|---|---|---|
| 사람 | 쓴다 | 브리프: 목적, 사람 행동 삼중항 1~3개, 혼동되면 안 되는 이웃 개념, 독자 |
| 사람 | 고른다 | 검증할 후보(생성 묶음, 외부 에이전트, 직접 낸 이름) |
| 사람 | 읽는다 | `<out>/report.md`의 표와 제외 근거 원문 |
| 사람 | 확인한다 | 규칙이 놓친 오독(설명문 직접 읽기) |
| 사람 | 정한다 | 이름 |

판단 기준(프로필):
- 이름은 `[대상]-[역할]`, 키워드 3개 이하. 이름에 **대상**이 없으면 처음 보는 사람이 대상을 알 수 없다(2026-11-04 실측: 대상 없는 후보 대부분이 '이름' 조건에서 탈락하고 데이터·신호·팀 정렬 도구로 읽혔다).
- 한 번이라도 오독이면 제외. 모두 제외되면 오독률 최저에서 고른다(예비 선택).
- 이름 충돌은 참고만 한다.
- 오독률 0%라도 안심하지 않는다: 규칙은 미리 적은 분야만 잡는다. 설명문을 직접 읽는다.
- 선택된 이름의 통과율이 낮으면 표본을 늘리거나 후보를 바꾼다(보고서가 경고한다).

외부 에이전트(다른 채팅 서비스)에 일을 맡길 때:
- 생성: `naming_profile.json`의 `generator.prompt_template`에 브리프의 목적·사람 행동만 넣어 준다.
- 답변: 새 대화창에서 이름 하나씩, `collect_samples.INSTR`(개발자) 또는 프로필 `perspectives.prompts`(사람 관점) 원문 그대로 준다. 받은 JSON과 모델·관점을 함께 기록한다.

## 3. 도구를 고치는 에이전트(C)

수정 프로토콜(`skills/modification-protocol/SKILL.md`, workflow-runner 원문)을 따른다. 이 하네스에 적용하면:

| 주체 | 행동 | 대상 | 명령·파일 |
|---|---|---|---|
| 에이전트 | 고정한다 | 문제 정의(기대 vs 실제, 사실·가설·미검증 구분) | 작업 메모 |
| 에이전트 | 찾는다 | 이미 성공한 기존 구현(작업 공간 먼저) | 서브에이전트 검색, 원본 직접 읽기 |
| 에이전트 | 쓴다 | 실패하는 테스트(먼저) | `tests/` |
| 에이전트 | 받는다 | 설계·테스트의 적대적 검토 | 별도 서브에이전트 |
| 에이전트 | 고친다 | 최소 구현(기존 코드 재사용, 원문 복사 시 출처·sha256) | `scripts/` |
| 에이전트 | 비교한다 | 기존 판정기 vs 새 판정기, 같은 표본 | `namecheck compare <git 커밋> <규칙>::<표본,…>` (차이 0 = 동일, 2 = 차이 있음) |
| 에이전트 | 지킨다 | 동점이면 기존안 유지 | `choose()` = runner.choose 원문 |

규칙:
- 기존 테스트는 모두 통과시킨다: `.venv/Scripts/python.exe -m pytest -q`(`pytest.ini`가 tests/만 모은다). formal/의 Lean 모델·차분 테스트는 `bash formal/name-harness/verify.sh`. 금지어 검사·빈칸·낱말 점검을 고치면 둘 다 돌린다.
- 선택 필드를 더할 때는 값이 있을 때만 `rule_hash`에 넣는다. 그래야 이미 받은 표본이 stale로 떨어지지 않는다.
- 판정식 자체를 바꾸면 `check_terms.JUDGE_VERSION`을 올린다.
- 규칙을 고치면 새 표본으로만 재판정한다.
- 동봉 실행기(`scripts/vendor/workflow_runner`)는 고치지 않는다. 원본이 바뀌면 다시 복사하고 `PROVENANCE.json`을 갱신한다(`tests/test_portable.py`가 어긋남을 잡는다).
- 실패 사례는 `naming_failures.json`에 남긴다. 단어로 잡히는 오독은 `risky_tokens.json`에도 넣는다(`tests/test_naming_failures.py`가 빠짐을 잡는다).

## 4. C를 쓰는 사람(D)

| 주체 | 행동 | 대상 |
|---|---|---|
| 사람 | 지시한다 | 고칠 문제와 판단 기준 |
| 사람 | 읽는다 | 기존안 비교 표(판정 줄, 다른 줄)와 실패 사례 기록 |
| 사람 | 정한다 | 기준 변경(프로필), 커밋·공개 |

## 기록된 교훈(요약, 원문은 naming_failures.json)

- 관점 지시문을 바꾸면 답변 어휘가 쉬워져 개발자 어휘 신호어에 안 걸린다. 그 관점의 설명문을 읽고 신호어를 보강한다(H10).
- 신호어가 의도와 겹치면 오탐이 섞인다. 단어보다 동작+결과 쌍으로 쓴다(H11).
- 이름 자체의 단어를 신호어로 쓰면 그 이름은 자기 때문에 제외된다(H8).
- 생성 프롬프트에 금지 목록을 넣으면 오히려 끌려간다(P9).
- 재표본 부트스트랩은 전수 집계보다 새 정보가 없다. 반복 검증은 답변자 재실험(지시문·모델)과 평가자 재실험(규칙 변형)으로 한다(P6).
